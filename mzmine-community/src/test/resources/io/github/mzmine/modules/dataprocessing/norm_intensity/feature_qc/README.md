# Feature-QC R reference fixtures

The CSVs were generated by the included R script with webR 0.6.0, R 4.6.0 and `stats` 4.6.0.
They use `stats::loess(..., degree = 1, family = "gaussian")`, with R's default interpolated
prediction surface, natural logarithms, and the explicit spans in the CSV. They are an independent
R comparison, not output from the unmodified pmartR package.

To reproduce with base R and its `stats` package:

```sh
Rscript generate_pmartr_feature_qc_fixture.R feature-qc-reference
```

The script generates all three CSVs and `fixture_metadata.properties`. Inputs, target values, fitted
R values, factors and fitting parameters are retained. No package installation beyond base R is needed.

The normalization design was checked against pmartR/qcrlsc commit
`5b5ee02657c72ba0727fb3ef2a9a001d057add45`. The original `normalize_qcrlsc.R` SHA-256 is
`712eb6bcff7d8c129115505f579ef315c2068688f82d5262a4b53d20eec8b6bc`.
That source refers to undefined `edata` in the `biomolecules_i` assignment where `e_data` exists.
No patch to that source is included or executed. These fixtures use base R and do not execute the
full qcrlsc package or its pmartR object/filter dependencies. They do not establish
unmodified-package parity.

## What the comparisons establish

- Every affine-log factor agrees within `1e-10`; the global log target agrees within `1e-12`.
- The two flat batches restore one target, `median(log(c(rep(10, 9), rep(20, 9))))`, and all their
  factors are checked against the R values within `1e-12`.
- Count-based missingness fixtures exercise the actual Java engine at and around the global and
  batch equality boundaries. They do not replace the minimum-QC checks.
- For the controlled nonlinear curve, the Java test reports the maximum absolute log-fit difference
  and RMSE over all 11 samples. With Commons Math 3 and the committed settings, the measured maximum
  is **0.00238824647826** log units and RMSE is **0.00130786247496**. The test deliberately treats this
  as a quantitative comparison of distinct solvers, not a pass/fail tolerance for scientific fit
  quality. It separately verifies the common target exactly.

The Java implementation uses a minimum of five QCs, exact elapsed time, configured robustness,
and nearest-boundary prediction policy. The R comparison uses robustness zero to match its Gaussian
family. The nonlinear measurements do not validate every span, robustness setting or extrapolation
scenario; those behaviors have separate engine tests.
